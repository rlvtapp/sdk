## Runtime middleware

Fetch and Axios clients accept `middleware` in their configuration.

```ts
import { createClient, type ClientMiddleware } from "@relevate/sdk";

const customerPolicy: ClientMiddleware = async (request, next) => {
  try {
    return await next({ ...request, query: { ...request.query, tenant: 'customer-a' } });
  } catch (cause) {
    throw new Error('Customer API request failed', { cause });
  }
};
const transport = createClient({ middleware: [customerPolicy] });
// Pass the same middleware config to the generated SDK constructor.
```

The first middleware is outermost. Call `next(updatedRequest)` at most once; request changes apply before serialization and authentication. Replace the returned response envelope to rewrite data, or return an envelope without calling `next` to short circuit. A short circuit bypasses remaining middleware, transport hooks and transport validation callbacks. Optional response shape checks still run after the completed chain. Middleware runs once per logical call; built-in retries remain inside `next`. Existing hooks keep their transport timing. Ordinary responses contain `status`, `contentType`, `data` and `headers`. Preserve native Fetch `Response` objects for streams, and Axios stream envelopes with a readable `data` stream.

## Response shape checks

Set `validateResponses: true` in client configuration to check declared buffered successful JSON response shapes, including responses returned or rewritten by middleware. Checks are disabled by default; a request can override the setting. `ResponseDecodeError` reports the failing path without response values. Extra fields and new enum strings remain accepted. HEAD, 204, SSE, error responses, and absent or unmatched response schemas are outside this scope. These checks cover structural types, required properties, nullability, and supported compositions, rather than all JSON Schema constraints.
